PEGS Supercoach Franchise v14.8.4 - End-to-End QA Report
================================================================
Date: 20 September 2026
Result: 65 PASS / 0 FAIL in isolated browser season simulation

Scope
-----
The test ran an isolated 2027 season from preseason setup through season close and 2028 rollover. It used synthetic SuperCoach master-list data and isolated browser storage so no live PEGS league data was changed.

Lifecycle covered
-----------------
1. New-season template, fixture generation/validation and activation gates.
2. Confirmed full SuperCoach master-list prerequisite and LISTED/UNLISTED reconciliation.
3. Current Roster vs Planner Mode, renewal source/terms and roster-window close readiness.
4. Trades preserving contracted price/position/expiry; delistings; roster legality and max 3 Rookies.
5. Preseason and mid-season Rookie elevations using current confirmed SuperCoach price/position.
6. Automatic preseason delisting of all unelevated Rookies and frozen draft-pool creation.
7. Pre-Season Draft, 3-round Rookie Draft lifecycle, contract types/expiries, overtime pick pushback and safe draft reversal.
8. Regular-season scoring rules, post-2026 bye counting, availability normalization and Round 10 mid-season gate.
9. Mid-season master list, roster window, Mid-Season Draft, 2.5-year Main contracts and scoring snapshot.
10. Top-4 PAGE finals progression, Grand Final, season close, premier/runner-up and 2028 rollover.
11. Recovery snapshot coverage and smoke-render of every main route.

Defects found and corrected during QA
-------------------------------------
- Contract renewals appeared in Planner Mode but had no submission/approval workflow. Added actionable preseason renewal requests using the confirmed preseason SuperCoach master list and standard 2-year Main terms.
- Frontend depended on RPCs not represented in the bundled SQL upgrade. Added direct draft-pick confirmation, backup baseline replacement and transaction-reversal RPCs, and brought ELEVATION/RENEWAL into the server proposal model.
- Server roster legality did not enforce the browser's maximum of 3 Rookie contracts or invalid Field-position rejection. Server/browser legality is now aligned.
- Server trade validation did not include conditional delistings when calculating the final roster. It now validates the whole transaction together.
- Draft reversal could remove a completed pick without safely reopening the correct lifecycle phase/snapshot. Reversal is now limited to the latest pick in the current session and rewinds draft/lifecycle state.
- Rookie Draft contract expiry was one year short. A Rookie drafted in 2027 now expires at the 2028 preseason.
- Mid-Season Draft Main contract expiry was one year short. A player drafted mid-2027 now has a 2.5-year term and renews before 2030, matching the 2026 historical contract convention.
- New scoring_snapshots state was not null-guarded in the direct draft RPC. Initial snapshot creation is now safe.

Backend/static integrity checks
-------------------------------
- 14/14 frontend Supabase RPC references have definitions across the schema + v14 upgrade + v14.8.4 SQL patch.
- New SQL references only known PEGS tables/functions from the bundled schema.
- SQL lexical checks: balanced dollar quotes, strings and parentheses; one BEGIN/COMMIT transaction.
- app.js, sw.js, config.js, league-data.js and vendor/pegs-xlsx.js pass Node syntax validation.
- supercoach-sync/index.ts passes TypeScript parsing/type syntax validation with a local Deno shim.
- Service-worker cache bumped to pegs-v14-8-4-e2e-qa-fixes.

Production verification boundary
--------------------------------
The destructive season/draft/finals test was intentionally NOT run against the live league database. This environment also could not retrieve the GitHub Pages deployment or connect to the live Supabase project, so authenticated live RPC/auth/network behaviour cannot be certified from here. The browser lifecycle and source/backend contracts are verified; production requires the included SQL patch and the included supercoach-sync Edge Function to be deployed before v14.8.4 should be treated as the live season baseline.
